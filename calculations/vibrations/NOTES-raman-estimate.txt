Lab L1c part B (5KE176 Exercise 3, Raman of benzocaine vs cocaine) -- cost estimate, NOT run at def2-TZVP
========================================================================================================
ECCE build of main f0178cc0f (9.5.3-dev); measured on niobium 2026-11-15, 4 MPI procs, nice 19.

ECCE option: Calculation Editor > Runtype Details > Frequencies box: "Raman Activities"
(ES.Runtype.Vibration.UseRaman -> %elprop Polar 1). With B3LYP (B88 exchange) ORCA cannot
do Raman analytically, so Frequencies Method must be Numerical (ECCE warns on Verify).
ECCE GAP, filed as #1058: with Method = Numerical the editor writes "Opt Freq NumFreq";
ORCA 6.1.1 takes "Freq" as analytic and stops at once (exit 55, "Third functional
derivative of a B88 exchange-containing functional"). Worked around by a Final Edit of
the input to "Opt NumFreq" (run_l1c.py does this edit after the editor's Save).

Measured
  benzocaine (C9H11NO2, 23 atoms) B3LYP-D3BJ/def2-SVP (223 bf), Opt + NumFreq + Raman,
  through ECCE (calculations/vibrations/orca-benzocaine-svp-raman), from an Open Babel
  3-D start: 4743 s wall in ECCE (ORCA 78.2 min):
     optimisation 11 cycles: SCF 207 s + gradients 128 s (~6 min)
     numerical frequencies 138 displacements (6N, central): 4326 s = 31.3 s each
  Single points EnGrad + Polar at def2-TZVP, 4 procs (calibration, run by ORCA directly):
     benzocaine 438 bf: 135 s (SCF 68, response 32, gradient 30)
     cocaine (C17H21NO4, 43 atoms) 808 bf: 544 s (SCF 306, response 135, gradient 95)

Model: one displacement = 0.75-1.0 x the cold single point (the SCF restarts from the
reference orbitals); 6N displacements; optimisation from a pre-optimised (def2-SVP or xTB)
start: benzocaine ~12 cycles, cocaine 25-40 cycles (flexible ester groups), each cycle
~SCF/2 + gradient. Other hosts: NerdEgg 6 physical cores assumed same per-core speed,
x0.74 (4/6 at 90 % efficiency); Kebnekaise one node 28 cores, x0.2 (4/28 at ~70 %
efficiency). Per-core speeds on NerdEgg/Kebnekaise were not measured.
